# webship

Odoo module **Koppeling Stoqflow by Data Forge** (`webship`): integration between Odoo and Stoqflow (Webship) for e-commerce logistics and warehouse operations.

Extracted from `Pivotal-Dataforge/flat-pro` with its git history preserved.

## Layout

One folder per Odoo version, each holding the addons for that version:

| Folder | Odoo | Contents |
|--------|------|----------|
| `18.0/` | 18.0 | `webship` |
| `19.0/` | 19.0 | `webship`, `webship_demo_skateshop` |
| `20.0/` | 20.0 | `webship` |

## Installation

Add the folder that matches your Odoo version (e.g. `<repo>/20.0`) to the Odoo `addons_path` and install the `webship` module.

Depends only on standard Odoo modules: `base`, `web`, `sale`, `product`, `purchase`, `stock`, `delivery`.

## Demo database: Woody's Skate Supply

`19.0/webship_demo_skateshop` turns a **fresh, empty** Odoo 19 database into a demo company that uses Stoqflow as its e-fulfilment partner. Install it from Apps (it pulls in `webship`, eCommerce, Manufacturing and the Belgian chart of accounts). Never install it on a production database: it renames the main company and creates warehouses, partners, products and orders.

What it sets up:

- **Company** Woody's Skate Supply BV (Antwerpen), Belgian chart of accounts, EUR, 21% VAT.
- **Warehouses**
  - `H800` Skate Workshop H800: own warehouse where components arrive and boards are assembled.
  - `SQF` Stoqflow Fulfilment: its stock location is flagged *Is Stoqflow locatie*, so receipts into it become Stoqflow purchase orders and deliveries out of it become Stoqflow orders.
- **Webshop** (Odoo eCommerce) selling tees, hoodies, beanies, socks and complete boards from the `SQF` warehouse. Backend sales also default to `SQF`.
  - Brand styling from the Woody's logo (electric blue, cyan, navy; Archivo Black / Space Grotesk), stored as website editor customisations so it stays editable.
  - Custom homepage (`views/website_templates.xml`, `static/src/scss/woody.scss`): hero, ticker, category tiles, featured products, workshop and Stoqflow fulfilment sections.
  - Illustrations for every product, variant colour, category and the homepage in `static/img/`. They are generated by `tools/make_images.py` (SVG rendered with headless Chromium); rerun it after changing a drawing. Replace `static/img/logo.png` to use another logo.
- **Routes**
  - Clothing: *Buy*, received directly in `SQF`.
  - Components: *Buy*, received in `H800`; not synced to Stoqflow (*Don't sync this product*).
  - Complete boards: *Manufacture* in `H800` (bill of materials: deck, 2 trucks, wheels, bearings, grip tape, hardware) + *Stoqflow Fulfilment: Supply Product from Skate Workshop H800* (H800 → transit → SQF).
  - Replenishment rules (manual trigger) for all of the above, visible under Inventory > Replenishment.
- **Documents**: received and delivered history, plus open documents that are pending for Stoqflow (process code `P`): a clothing restock PO, a resupply of complete boards from the workshop, and webshop and B2B orders.

Stoqflow API credentials are not set and the Stoqflow crons are switched off. To sync for real, enter sandbox credentials under Settings > Stoqflow, run *Fetch companies and warehouses*, link the `SQF/Stock` location to the Stoqflow warehouse, and switch the crons back on.
